Part 1.1: Convolutions from Scratch

I implemented 2D convolution in two ways: one version with four nested loops and one version with two loops plus NumPy array operations. In both versions I flipped the kernel before applying it, so the operation is convolution rather than correlation. I used zero padding to keep the output the same size as the input.

Four-loop implementation:

kernel = np.flip(kernel)
kh, kw = kernel.shape
padded = np.pad(img, ((kh // 2, kh // 2), (kw // 2, kw // 2)))
out = np.zeros_like(img, dtype=float)

for i in range(img.shape[0]):
    for j in range(img.shape[1]):
        for a in range(kh):
            for b in range(kw):
                out[i, j] += padded[i + a, j + b] * kernel[a, b]

Two-loop implementation:

kernel = np.flip(kernel)
kh, kw = kernel.shape
padded = np.pad(img, ((kh // 2, kh // 2), (kw // 2, kw // 2)))
out = np.zeros_like(img, dtype=float)

for i in range(img.shape[0]):
    for j in range(img.shape[1]):
        patch = padded[i:i + kh, j:j + kw]
        out[i, j] = np.sum(patch * kernel)

The two custom implementations matched each other with max error 5.55e-17. Compared with convolve2d, the box filter error was 2.44e-15, and the derivative filter errors were 0.0.

On a 150x150 crop with the 9x9 box filter, the four-loop version took about 0.36s, the two-loop version took about 0.034s, and scipy.signal.convolve2d took about 0.0015s. The two-loop version is faster because each output pixel uses a NumPy dot product instead of looping over the kernel entries in Python, and SciPy is much faster because the inner loops are implemented in optimized compiled code.

Part 1.2: Finite Difference Operator

I convolved the cameraman image with finite difference filters D_x = [1, 0, -1] and D_y = [1, 0, -1]^T. From these derivatives, I computed the gradient magnitude and thresholded it to create a binary edge image.

I tried thresholds 0.10, 0.15, 0.20, and 0.25. I chose 0.20 because it keeps the main cameraman and camera edges while removing more of the background noise than the smaller thresholds.

Part 1.3: Derivative of Gaussian Filter

The finite difference result is noisy, so I first smoothed the image using a Gaussian filter made with cv2.getGaussianKernel(9, 1.5). After blurring, I repeated the derivative, gradient magnitude, and thresholding steps. The resulting edge image is cleaner because the Gaussian removes high-frequency noise before differentiation.

I then created derivative-of-Gaussian filters by convolving the Gaussian filter with D_x and D_y. This lets us combine smoothing and differentiation into one convolution per direction.

To verify the single-convolution DoG method, I compared it with the blur-then-derivative method away from the image boundary. The max differences were 1.06e-15 for x, 1.15e-15 for y, and 1.13e-15 for gradient magnitude, so the two methods agree up to numerical precision.

Part 2.1: Image Sharpening

I implemented unsharp masking. First I blur the image with a Gaussian filter to get the low-frequency component. Then I subtract the blurred image from the original to get high frequencies, and add those details back with a scale factor alpha: sharpened = image + alpha * (image - blurred). Equivalently, this can be written as one convolution with the unsharp mask kernel K = (1 + alpha) * delta - alpha * G.

Increasing alpha makes edges and texture stronger, but too much sharpening starts to create halos and an unnatural contrast around strong edges.

I also tried the same process on another image of my choice. The sharpened output makes architectural edges, window details, and building textures more visible.

For evaluation, I blurred a sharp image and tried to sharpen it again. The resharpened image recovers some edge contrast, but it does not fully match the original because blur removes high-frequency information that cannot be perfectly recovered.

Part 2.2: Hybrid Images

I created hybrid images by combining the low frequencies of one aligned image with the high frequencies of another: hybrid = blur(low image) + high image - blur(high image). The result changes with viewing distance because nearby viewing shows high-frequency details more strongly, while far-away viewing emphasizes the low-frequency structure.

Original vs aligned inputs

Before filtering, I aligned each pair so the main features were in the same position.

Favorite result: Orange cat + dog

I chose the cutoffs by checking the hybrid at several displayed sizes. For panda/cat I used sigma_high = 1.2 and sigma_low = 0.5. For Nutmeg/Derek I used sigma_high = 8.0 and sigma_low = 16.0. For orange cat/dog I used sigma_high = 5.0 and sigma_low = 4.0.

Larger sigma_high removes more low-frequency shape from the high-frequency image, while larger sigma_low keeps only coarser structure from the low-frequency image. Orange cat + dog was my favorite because the dog face reads from far away and the cat texture still shows up close.

For each pair, I also plotted the process images and the log magnitude of their Fourier transforms: high-frequency input, low-frequency input, high-pass component, low-pass component, and final hybrid.

Part 2.3: Gaussian and Laplacian Stacks

I implemented Gaussian and Laplacian stacks without downsampling. Each Gaussian level is made by applying another Gaussian blur to the previous level, so all stack images keep the same dimensions. The Laplacian stack stores the difference between adjacent Gaussian levels, with the final level storing the most blurred image. 

gaussian = [image]
for level in range(1, levels):
    gaussian.append(blur(gaussian[-1], sigma))

laplacian = []
for level in range(levels - 1):
    laplacian.append(gaussian[level] - gaussian[level + 1])
laplacian.append(gaussian[-1])

For the Oraple, I also built a Gaussian stack for a vertical mask. At each frequency band, I combined the apple and orange Laplacian levels using the corresponding blurred mask level, then summed all blended levels to reconstruct the final image.

As a check, summing the Laplacian stack reconstructs the original image: the max reconstruction errors were 2.78e-17 for the apple and 2.78e-17 for the orange.

The direct split has a visible boundary because all frequencies switch at the same place. The stack blend is smoother because the transition is handled separately at each frequency band.

Part 2.4: Multiresolution Blending

I reused the Gaussian and Laplacian stack code from Part 2.3 and moved the actual blending into a general blend_images function. For each level, I combine the Laplacian bands with the matching Gaussian mask level: L = mask * L_A + (1 - mask) * L_B. Summing those blended levels reconstructs the final image. 

for la, lb, m in zip(laplacian_a, laplacian_b, gaussian_mask):
    blended.append(la * m + lb * (1 - m))

result = sum(blended)

I used two image pairs with irregular masks. For the first one, I used the apple and orange cropped from the side-by-side source image and blended them with a wavy seam. The same function works because the mask stack has the same dimensions as the input images at every level.

Most Important Thing I Learned

The biggest thing I learned is that a visible seam is usually not just about where two images meet. It depends on frequency. Sharp masks work badly because they force high and low frequencies to change at the same hard boundary. Once I used a Gaussian stack for the mask and blended each Laplacian band separately, the transition became much more natural.
